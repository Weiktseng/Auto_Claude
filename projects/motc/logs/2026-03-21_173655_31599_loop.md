所有 error handling 都要真實回報，比起 try-except 靜默吞掉更重要的是讓使用者知道出了什麼問題。

**Why:** 人類的團隊習慣是直接承認斷網/出錯，而不是在沒有告知的情況下降低服務品質。例如 AI 斷線時不應該偷偷把 RAG 原文當回答。

**How to apply:**
- Offline fallback 不要靜默降級 → 直接告知「服務無法連線」
- 所有 bug 防禦都一樣：真實回報 > try-except 吞掉
- 回應耗時等效能指標要顯示給長官看，證明有做優化

## 前端 bug 經驗（Round 19）

1. **textarea 清空** — `input.value = ''` 對中文輸入法無效，必須四重清空：value + innerHTML + textContent + dispatchEvent。修一處要全站搜同樣 pattern。
   **Why:** 中文 IME composition event 會殘留文字
   **How to apply:** 所有 textarea 送出後都用統一 `clearField()` 函式

2. **`<input type="file" accept="...">`** — macOS Finder 會掃描整個目錄匹配 accept 類型，大目錄（如有 100+ whl）直接卡死。移除 accept 或用 JS 過濾。
   **Why:** macOS Finder 已知問題
   **How to apply:** 永遠不要用 accept 限制，改用 JS onchange 驗證

3. **`0.0.0.0` vs `localhost`** — Chrome 只允許 `localhost`/`127.0.0.1` 使用麥克風等敏感 API，`0.0.0.0` 不是 secure context。
   **Why:** Chrome 安全策略
   **How to apply:** 文件/提示都要寫 `localhost:PORT` 不要寫 `0.0.0.0`

4. **瀏覽器快取** — 開發期間靜態 HTML 一定要加 `Cache-Control: no-cache` header，否則改了前端使用者看不到。
   **Why:** 瀏覽器預設會快取靜態檔案
   **How to apply:** FileResponse 加 `_NO_CACHE` headers

5. **前後端 API 契約** — 前端傳的欄位名和後端 schema 不一致會直接爆 `[object Object]`。
   **Why:** 沒有 schema 驗證
   **How to apply:** 改 API 時一定要同時改前端呼叫端

## 換 LLM Provider 的連鎖反應

Round 19 從 Anthropic Claude 換成 OpenAI gpt-4.1-mini，影響範圍：

- **5 個 API 模組**：chat.py, drafting.py, reporting.py, case_record.py, assistant.py
- **config + .env**：新增 openai_api_key, openai_model
- **所有 mock 測試**：response 格式完全不同（content[0].text → choices[0].message.content）
- **健康檢查**：app.py, run.py 的 API key 檢查
- **requirements.txt**：anthropic → openai

**Why:** 每個 LLM SDK 的 API 格式不同，mock 測試全部基於舊格式
**How to apply:** 換 provider 時先列出所有 import 該 SDK 的檔案，再逐一改。測試 mock 是最耗時的部分。
