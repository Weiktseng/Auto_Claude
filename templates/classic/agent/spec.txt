# <專案名稱> — 規格書

> **填寫規則**：
> - 每條需求必須有「編號 + 一句話需求 + 優先級」三個部分
> - 編號可隨時細分：1 → 1.1 → 1.1.1（不用一開始就分到最細，做到那裡再拆）
> - 優先級只有三層：P0（不做就不能 demo）、P1（demo 能過但缺了會被問）、P2（有很好、沒有不影響交付）
> - Dev 按 P0 → P1 → P2 順序做。同優先級內按編號順序
> - 需求可以帶「說明」子段落解釋細節，但一句話需求本身必須能獨立被理解
> - 本檔案是客戶/PM 的原始契約，Phase 切分策略寫在 context.md，不要改這裡
